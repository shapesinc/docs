A team project works better when people can contribute directly, see the same draft, and understand the next step. shapes.inc brings your team and a shape into one chat to research, make things, and work through decisions together.

Use one chat for a project and [threads](/threads) for focused work within it. Each person brings their expertise and access; the shape helps organize the discussion and carry out the work you request. This can be a class project, a volunteer group, or work with colleagues.

## Why a shared chat beats a private tab

Suppose your group is preparing a new website. Maya knows the audience, Drew maintains the code, and Lee has the event details. They can put those inputs in the same conversation, ask the shape for a draft, and review it together. Corrections reach the shape directly instead of one person copying answers between separate chats.

Ask for a recap that separates confirmed decisions, open questions, and assigned next steps. Keep the current brief visible in the chat. When work moves into a thread, put new requirements into that thread too; later main-chat messages do not automatically become part of its conversation context.

## Set up a team chat

1. Choose [New chat](/create-a-chat) for the project and select the people to invite. Under **Shapes**, select **Auto** or choose an existing shape if you want an assistant. Making a custom shape is optional.
2. Use [Agent mode](/chat-and-agent-modes) for research, files, and actions. Add the goal, constraints, and review expectations to [Custom Chat Instructions](/custominstructions-chats).
3. Share the relevant [files](/files-and-attachments) and links. Name who will check the content, the implementation, and the final result.
4. Set up the specific app, Code Project, or computer the task needs. Review its access separately from membership in the chat.
5. Adjust [AI replies](/designing-social-intelligence) so the shape participates at useful moments, and ask for the first concrete comparison or draft.

For example:

> Help us choose what belongs in our first release. Maya will review the audience and copy, Drew will review the implementation, and Lee will confirm the dates. Compare our proposed scopes against the deadline, identify missing information, and give us a brief we can correct together.

Moving from Slack? [Import your history, keep channels in sync, and post GitHub, Linear, or Ramp updates into a chat](/slack-and-hooks).

## Share one premium engine across the team

If your team chooses a premium AI Engine, an available [chat credit balance](/how-to-purchase-credits-for-a-chat) can fund eligible responses. Review [AI Engine options](/aienginecheatsheet) and [credit controls](/credits#plan-paid-work-with-your-group), including each person's **Don't use my credits** preference and the owner's **Keep the chosen AI Engine** setting.

A shared chat does not split every charge equally or combine everyone's allowances. Hosted coding has [per-user limits](/faq/how-do-free-coding-agent-limits-work), voice has its own funding rules, and an external agent or local coding setup may use a separate provider account. Check **Generation details** on a reply and the relevant task's result instead of assuming all work uses the same balance.

## What an AI teammate actually does

### Bring information from personal or shared apps

For a planning meeting, Maya can connect her calendar and ask for her availability; Drew can share his availability in a message. The shape compares the information they supplied and proposes times. If Maya then asks it to create the agreed event for named invitees, check the resulting calendar event. The comparison itself has not created one.

[Personal app connections](/connected-apps) are used for that person's requests and authorized scheduled work. Other members do not gain access merely by joining the chat. A reply can still share information retrieved for its requester with the group, so say which result you want brought into the conversation.

Supported work apps, including Notion and Linear, also offer [a separate connection shared with a chat](/connected-apps#share-an-app-with-a-chat). If Maya explicitly shares the project account, eligible members can ask the shape to use it in that chat. Drew might request an update to the agreed Notion planning page; the group can review the returned summary and open the actual page. The person who connected the account manages its sharing. Gmail, personal calendars, and GitHub do not offer this shared-app option.

An explicit request can authorize a supported action without another confirmation. Say whether you want a draft, an edit, or a completed send, and name the destination. A mention or private link alone does not grant access. [Custom MCP connections](/shapeskills#connect-an-outside-service) have their own public, per-member, or shared-key setup.

### Review documents and produce a shared result

Ask each person to attach the material they own and explain what needs review. A shape can compare the supplied information, find disagreements, and draft a brief or presentation outline. Put detailed review in a thread, let people check their own contributions, and ask for a revised downloadable file after the corrections are agreed.

Open the actual [file](/files-and-attachments) and check the content and format before using it. The chat is a place to discuss revisions; it is not automatically a shared document editor. To update a document in another app, request that action through the relevant connection and verify the saved document there. See [planning and making things together](/plan-and-build-together#make-documents-images-and-slides-together) for the full workflow.

### Build and review code in the right place

For an existing repository, a chat owner can set up a [Code Project](/connect-your-computer#code-projects). It starts private. After its owner shares it, current and future members can run work and publish changes using the project's saved environment, including secrets, and edit its environment and instructions. The owner's personal GitHub connection remains separate.

Drew can ask for a fix in that project while Maya reviews the preview and Lee checks the requirements. Ask the shape to report the changed files, checks that ran, failures, and where the result lives. A local edit, a pushed branch, a pull request, and a deployed site are different milestones; specify the next step and verify the actual link or files.

For files or tools on Drew's own machine, [connect that computer](/connect-your-computer) instead. Drew can request work himself, including from his phone while the computer remains online. Other members need a saved computer share to request work there; **Read-only** supports review, while **Can make changes** allows editing with the local setup. Sharing a Code Project does not share the computer, and sharing a computer does not transfer its owner's account to the other members.

[Hosted Claude Code or Codex](/faq/how-do-free-coding-agent-limits-work) runs through shapes.inc rather than that computer. An [external agent](/ai-agents) is another participant run by you or a teammate, with its own host and tools. Choose the intended environment in the request so the group knows where to inspect the result.

## Patterns that work

### Give people distinct review roles

Assign contributions people can actually check: one person supplies source material, another checks the facts, and another tries the finished output. Ask the shape to keep unresolved questions visible and revise the work using their replies. If several shapes or external agents participate, give each a clear task so they do not all repeat the same answer.

### Keep a focused thread, then share the conclusion

Use a [thread](/threads) to investigate a bug or compare proposals within the same chat. The thread has the chat's audience. Once people agree, post the conclusion in the main chat or ask the shape to send that specific update there. A [branch](/branch-off) creates a separate chat with copied context; choose it when that is the conversation you want to continue.

### Hand off one task with the right context

Ask a shape to [start a task chat](/tasks#hand-off-work-to-another-chat) with the named people and the specific information they need. For example, carry over the approved scope and deadline so two teammates can prepare a test checklist. Open the task chat to review the actual work; creating it is only the beginning. Its members do not gain all of the requester's accounts or other conversations.

An external agent can also take a named part of the work, but its owner must keep its responder running if the group expects ongoing replies. Joining a chat and monitoring it are separate steps; follow the [external-agent guide](/ai-agents) for setup and verification.

### Schedule a follow-up or watch an update

For a recurring team recap, name the chat, time, time zone, and what to include. The requester checks the saved schedule in **Settings → Tasks**, and the group reviews the posted result when it runs.

For a specific update, someone with the right personal connection can ask: “Watch this GitHub pull request and tell this chat when review is requested, then stop.” The [watch](/tasks#watches-and-scheduled-checks) uses its creator's access; the update is visible to the chat. A broad request to watch for anything needing that person's attention uses a private chat instead. Watches are periodic checks, and later runs still need the creator's membership, connection, and required usage allowance or credits.

Use **Tasks** to review or cancel follow-ups. If the creator marks the chat Completed, their scheduled checks pause; another member marking it Completed does not pause everybody's tasks. Follow the [timing and recovery guide](/tasks#timing-and-limits) when a schedule does not run as expected.

## Keep the chat sane

Keep the goal and current decision visible. Use [Custom Chat Instructions](/custominstructions-chats) for lasting expectations, [AI replies](/designing-social-intelligence) for participation, and [moderation](/moderation) for chat controls. Ask for evidence, a draft, or a completed action as appropriate, and review the resulting file, app record, or code change together.

Before closing a project, check unfinished work and cancel follow-ups you no longer need. [Completed chats](/completed) help organize the sidebar; completed messages and files remain separate from work still running in an outside service or on someone's computer.
