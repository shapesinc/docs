Connect a computer to an [Agent chat](/chat-and-agent-modes) and a shape works on the files and tools there: the budget for a family trip, a class project's code, or the build your friend needs help fixing. The chat shows requests and results while the shape works on the computer you authorize.

You set your computer up once, choose which chats can use it, and remove access at any time.

<Warning>
  When you allow a chat, shapes there can run commands, read and change files, use apps, control the keyboard and mouse, see your screen, and use the network, within the system permissions you give your computer. Results you ask for may be visible to other people in the chat. Only allow chats you trust.
</Warning>

## Before you begin

Check that the computer can run the shapes.inc app:

- **Mac:** The app needs macOS 13.5 or later.
- **Windows:** The app runs on 64-bit Windows.

## Choose where the work runs

- **Your connected computer:** use files, apps, and tools on that machine. Coding tasks use your own Claude Code or Codex there by default; see [choose the account for local tasks](#choose-the-folder-and-account-for-local-tasks). The computer needs to stay online.
- **Hosted Claude Code or Codex:** use coding agents run by shapes.inc. They do not use your computer or its local sign-in. See [hosted coding limits](/faq/how-do-free-coding-agent-limits-work) for allowances and billing.
- **Code Projects:** connect a GitHub repository and its saved environment to coding work in a chat. This is separate from connecting a personal computer. A project starts private and has its own [sharing controls](#code-projects).

Name the computer or project in your request, especially when you have both personal and shared access. For example, “Review the project on Maya's shared computer using her local Codex.” A shape should report an unavailable computer or agent rather than silently moving the task somewhere else.

With your computer connected and online, shapes use it for your own code and data, such as a repository, a local tool, or a project database (read-only), instead of saying they can't check from there. This works on the free engine too.

## Get the desktop app

The shapes.inc app for Mac or Windows connects the computer it runs on. Setup is three steps: download the app, sign in, and select **Connect this Mac** or **Connect this PC**. No Terminal or install command is needed. Connecting is optional: you can use the app only for your chats and connect later.

On the web, the sidebar shows a **shapes.inc for Mac** or **shapes.inc for Windows** card with **Get the app**. **Dismiss for today** hides it until tomorrow. You can also find the downloads under **Settings** → **Download the app**.

### Install on a Mac

1. Go to [shapes.inc/downloads](https://shapes.inc/downloads) and select **Download for macOS**.
2. Open the downloaded file and drag shapes.inc to the **Applications** folder.
3. Open shapes.inc from Applications.

If you open the app straight from the downloaded file, it asks you to **Move shapes.inc to Applications** first, because updates don't work from there. Select **Show in Finder** to move it, or **Open without moving** to use it where it is.

### Install on Windows

1. Go to [shapes.inc/downloads](https://shapes.inc/downloads) and select **Download for Windows**.
2. Open the downloaded installer and follow the installation steps.
3. Open shapes.inc from the Start menu.

On Windows, the steps below are the same, with **This PC**, **Connect this PC**, **Use this PC**, and **Reconnect this PC** in place of the Mac names. The app's menus are under **File** and **Help** instead of the **shapes.inc** menu.

### Sign in through your browser

On first launch, a **Set up shapes.inc** window takes you through setup one step at a time.

1. On **Welcome to shapes.inc**, select **Continue with** your browser. To pick a different one, select **Use another browser**, or choose **Copy sign-in link** and open it in any browser. On Windows, select **Sign in**.
2. In the browser, sign in or create an account if you need to. On **Sign in to shapes.inc**, select **Continue as** your name. Only continue if you started this sign-in from the app.
3. The app comes back on its own, signed in.

If sign-in doesn't finish, select **Try again** in the app. To sign in later, choose **shapes.inc** → **Sign In…** in the menu bar (**File** → **Sign In…** on Windows). It shows only while you're signed out.

### Connect this Mac

After you sign in, setup offers **Connect this Mac**. If you chose **Not now**, open it any time from **shapes.inc** → **Computer connection…** in the menu bar (**File** → **Computer connection…** on Windows), or from **Settings** → **Computers** → **This Mac**.

1. Select **Connect this Mac**. While it's connecting, you can select **Cancel**; quitting the app during setup also cancels it.
2. On **Turn on permissions**, select **Allow** or **Open Settings** for each permission you want to give: **Keyboard and mouse** and **Screen recording**, plus the optional **Protected files** and **App control**. macOS asks once for each, and the list updates on its own as you allow them.
3. Select **Continue**, then **Start chatting**.

All your chats can use this Mac. **Use in all my chats** is on when you connect: every chat you're in uses this computer and your last folder, including chats you already had and group chats. An earlier chat picks the computer up the first time you open it in the Mac or Windows app, or send a message in it. In a group chat it only works for your own requests; to let other members use it, [share it with them](#allow-a-chat-to-use-it). Public chats aren't included, and a chat you disconnected stays disconnected. Turn **Use in all my chats** off in **Connect your computer** if you'd rather allow every chat yourself. **Settings** → **Computers** shows the computer as **This Mac**, with each permission marked **Allowed** or with **Open System Settings**.

This Mac **stays connected when you quit shapes.inc**: closing the window or quitting the app keeps it available to the chats you allowed, as long as it's on and online. When you reopen the app, the connection can pause for a moment while it checks your account.

To stop, select **Disconnect this Mac** in **Settings** → **Computers** or in **Computer connection…**. A disconnected Mac stays on your account; select **Reconnect this Mac** to use it again. **Remove computer** removes it from your account and stops access in every chat.

### Update the app

- **Mac:** choose **shapes.inc** → **Check for Updates…**. The update installs, the app reopens, and you stay signed in. If your copy of the app doesn't have **Check for Updates…**, download the current version from [shapes.inc/downloads](https://shapes.inc/downloads) once and replace the old one in Applications.
- **Windows:** choose **Help** → **Check for Updates…**, then **Download update**, then **Restart and install**. The app reopens on its own.

## After you connect

Your computer appears under **Settings** → **Computers** as **Online** or **Offline**. Keep it on and connected to the internet while shapes work on it. If it goes offline, it reconnects when it's on, signed in, and online, and its chat permissions are saved. Open **Permissions & background status** on a computer to see which system permissions it has.

### Use your computer from your phone

After setup, open the same shapes.inc account on your phone, enter the group's Agent chat, and use **+** → **Connect your computer** to choose your online computer and allow the chat. Ask the shape to read a named file or run a task there, then review its reply on your phone. The work still runs on the connected computer, which must stay on and online. Other chat members can read what the shape shares in the conversation; they do not gain access to your machine because you are using it from your phone.

### Connect with a code

If your computer shows a setup code or QR code, you can approve it from the iPhone app. In **Settings** → **Computers**, or in a chat's **Connect your computer** dialog, find **Have a code from your computer?** and select **Scan code** or **Enter code**. Check the computer it shows, then approve it. Scanning with the camera has been improved and is still being watched; if it doesn't read the code, use **Enter code**.

## Allow a chat to use it

1. In an Agent chat, open the composer's **+** menu → **Connect your computer**. In the desktop app, you can also select **Use this Mac** beside the message box, or the connect link in a shape's reply when it asks for your computer.
2. Select **Allow in this chat**.

If you opened the dialog from a shape's reply and the computer is online, the button reads **Allow and continue**. It allows the chat and asks the shape to resume your request, so you don't need to retype it.

Allowing a chat lets your own requests there use your computer. Other members can't use it unless you [share it](#share-your-computer-with-chat-members).

To stop, open **Connect your computer** again and select **Remove chat access**. **Remove computer** in **Settings** → **Computers** removes it from your account and stops access in every chat.

An account has one computer. Connecting a new Mac or PC replaces the one you had: the earlier computer is removed and your chats use the new one. Chats you disconnected stay disconnected.

### When a shape asks for your computer

If you ask for something that needs your own computer, a setup card appears under the shape's reply. It shows once per conversation and depends on where you are:

- **No computer yet, on a Mac or Windows browser:** **shapes.inc for Mac** or **shapes.inc for Windows** with **Download**. If the app is already installed, select **Already installed? Open in app**; after downloading, the button reads **Open this chat in the app**.
- **No computer yet, on a phone:** **Get shapes.inc on your computer**. Select **Copy download link** and open it on the Mac or PC you want to use.
- **In the desktop app:** **Connect this Mac** or **Connect this PC**.
- **A computer is already set up:** **Use your computer** → **Choose computer**.

While you finish setup, the dialog shows **Waiting for your computer…**. When the computer appears, select **Allow and continue** and the shape picks up where it left off.

## Approve requests in the chat

When a task on your computer needs a permission or an answer, the question appears in the chat for you to approve or answer. Nothing is chosen for you, and the task continues only after you respond. Only you can answer for your computer.

In the Mac app 1.24.45 or later and the Windows app 1.1.8 or later, Claude Code uses your own permission settings: your allow, ask and deny rules and your permission mode. It asks in the chat when those settings call for it, for example a command that matches one of your ask rules, or a permission mode that asks before it acts. In auto mode, which it uses when you haven't chosen a mode, Claude Code decides most actions itself without asking, and that can include changing files outside the task's folder. When it does ask, the request shows the exact command or file and its folder, with **Approve once** and **Deny**. Approve once and the same session continues. Deny and it carries on without that step; the result lists what was denied.

To stop a coding task, select **Stop** in its task card. A task that is ending shows **Stopping…**. While a shape is still replying, a pill above the message box says so, for example **Tod is working**. Open it and select **Stop** on the reply to stop that reply and the computer tasks it started.

## Ask about the computer itself

Shapes can check your computer directly instead of giving you manual steps: which Wi-Fi network it's on and which networks are nearby, its IP address, battery, free disk space, settings, installed apps, or where a file is.

Ask in the chat:

```text wrap
Which Wi-Fi network is my laptop on right now?
```

```text wrap
Find the PDF I downloaded this morning and tell me what it's about.
```

The computer must be online and allowed in that chat. If you've set it up but haven't allowed this chat yet, the shape offers a link to [allow it](#allow-a-chat-to-use-it) rather than guessing. Shapes can check only a connected computer, not your phone's settings.

## See and use your Mac's screen

Shapes can work in an app on your Mac while you keep using it. A shape looks at that app's window, even behind your other windows, then clicks, types, scrolls or uses its menus there, and looks again to check what happened. Your pointer, keyboard and the app in front stay yours: the shape never moves your pointer or brings the app forward.

While it works, the shape shows its own pointer with its name on it, so you can see where it's acting. A look at your whole screen is only a look; to act, the shape works in the app itself.

A few commands, such as **Save**, **Copy** and **Undo**, only work in an app that's in front. For those, the shape makes the app active for a split second, without bringing its windows forward, then puts your app straight back. It does this only when you haven't typed for a moment and the app's window is on the desktop you're using; otherwise it waits and tries again later, or asks you. After a save, it checks that the file was written.

This works in chats you've allowed, and for members you've shared with **Can make changes**. **Read-only** shares can't control the screen.

The Mac needs **Keyboard and mouse** and **Screen recording** allowed. If either stays off, see [Screen or keyboard control doesn't work](#screen-or-keyboard-control-doesnt-work).

## Hand coding work to Codex or Claude Code

Shapes can hand parts of a task to Codex or Claude Code on your computer. Ask for one by name, or let the shape choose. The result comes back in the task card and the shape's summary.

The shape starts the task as soon as you ask and gives your agent a brief it can act on by itself: what you asked for, with its meaning and details unchanged, plus what the chat knows that your agent can't see. Small talk around the request is left out. It doesn't read your files first, plan the work for it, or add limits you didn't ask for. Your agent runs the way it runs for you:

- **Your settings:** your Claude Code or Codex sign-in, settings and permission mode. Claude Code asks in the chat only when those settings call for it.
- **Your folders:** it edits where the task needs, including other folders and repositories on that computer.
- **Your images:** images you attach to the request go to the agent with it.

Claude Code has its own sign-in, separate from the Claude app, so being signed in to the Claude app isn't enough. If the shape says Claude Code is signed out, select **sign in to Claude Code** in its reply once on that computer, or run `claude auth login` in Terminal, then ask again. If you sign Claude Code or Codex in through your shell profile, for example an API key or token in `~/.zshrc`, the Mac app uses that too from its next update.

To keep it from changing anything, say so in the request:

```text wrap
Have my Claude Code find why the page goes blank when I scroll on my phone. Don't change anything.
```

With Mac app 1.24.46 or Windows app 1.1.9 and earlier, your agent edits only inside a Git worktree, so the shape creates one first, and it gets links to your images instead of the images.

Ask a shape to remember a preference for this chat, then check that it confirms saving it. You can review saved preferences in [Memory](/memory):

```text wrap
Always use a thread and my local Codex for code changes in this chat.
```

### Follow a coding task

When a shape uses your own Claude Code or Codex, it replies as soon as the task starts, with a task card. The card shows:

- the session name, and for you, **Open in Claude** or **Open in Codex** in the shapes.inc app on the computer that runs it
- what the agent is doing now, and how long it has run
- any request waiting for your approval
- **Stop**, for you as the computer's owner

When the task ends, the card shows the result and the shape posts a short summary in the chat. A task that finishes its work shows **Done**, even if you denied a step along the way. Select **Details** to see what was denied.

### Open a shape's coding session

When a shape uses your own Claude Code or Codex, it works in a session named for the shape and the task, for example "Tod: Release checklist TODO.md". You can open that session on the computer that runs it.

In the shapes.inc app on that computer (Mac app 1.24.46 or later, Windows app 1.1.9 or later):

- Select **Open in Claude** or **Open in Codex** on the task card.
- Or select a link to the session in a message.
- The session opens in the Claude app's Code tab or in the Codex app.
- From there you can follow along or take over.

If you don't see the button, update the app.

On your phone or another computer, the session exists only on the computer that runs it:

- The card shows that your computer runs the task.
- Session links in messages show as plain text.

You can also open the session yourself on that computer:

- **Codex:** find it in the Codex app's thread list.
- **Claude Code:** run `claude --resume` in a terminal and pick the session by its name.

While a Claude Code session is open in the Claude app or a terminal, the shape doesn't send it follow-ups, so only one of you writes to it at a time. A session you opened from the card counts as open in the Claude app. The shape tells you so instead of starting another session: continue there, or close it there and tell the shape, and it sends your follow-up to the same session.

The shape can send follow-ups to the same session, read it, check whether it's still working, and stop it. A follow-up on the same work goes to the same session, even after it has finished or when its files are now in another folder. A different task, even in the same folder, gets its own session.

If Codex is set to an engine your ChatGPT account doesn't offer, the task uses your account's default engine and the shape's reply says so.

### Choose the folder and account for local tasks

In the desktop app, select **Use this Mac** (or **Use this PC**) beside the message box in an Agent chat. Then:

- **Folder:** select **Choose** or **Change** to pick where local tasks work. Your chats reuse your last folder unless you picked another one there.
- **Local task account:** choose **Use Claude account**, **Use Codex account**, or **Use shapes.inc credits**. Your own Claude or Codex account uses the sign-in already set up in Claude Code or Codex, not shapes.inc credits.

If you haven't chosen, a coding task uses your own signed-in Claude Code first, then Codex, on your own accounts with no shapes.inc credits. If neither is ready, it uses the built-in agent on shapes.inc credits. A **Use shapes.inc credits** choice saved before November 10 now counts as not chosen, so choose it again if you want credits to pay.

### Use my coding instructions

**Use my coding instructions** is on by default in the **Connect your computer** dialog when the chat has your computer. It reads `~/.claude/CLAUDE.md` and `~/.codex/AGENTS.md` from that computer, the same files Claude Code and Codex use, so coding tasks follow your repositories and rules. The files are read when a task runs. The dialog lists each file it found with its size and full text. Turn it off anytime.

## Code Projects

Code Projects connect GitHub repositories for code tasks in an Agent chat. They're under **AI settings**, which chat owners can open; in a DM with a shape, you can open it yourself.

1. Open the chat's **Settings** → **AI settings** → **Code Projects**.
2. Select **Connect GitHub**, or **Add Org** to install the shapes.inc GitHub App on another account or organization.
3. Select **New Project**, choose the **GitHub account** and **Repository**, and add optional **Workflow steps** and **Project instructions**.
4. Select **Create Project**.

New projects are private: only you can use them. To let the chat use one, open the project's editor and select **Share with members**. Read what members will be able to do, check the box to authorize them, and select **Share with members** again. Current and future chat members can then run code and publish changes using the project's repositories and saved environment, including secrets, and can edit its environment and instructions. Your personal GitHub connection stays private. **Stop sharing** removes future access but doesn't undo changes already published or files already downloaded.

Projects keep going after the first step. Shapes can continue in the same repository, keep results from background runs, and push a branch without opening a pull request when you ask. To change an open pull request, paste its link and ask for the follow-up edits; they're pushed to that pull request. This doesn't work for closed pull requests, pull requests from forks, or a branch that has moved on.

Shapes can also read a pull request's CI: its named checks, workflow runs, jobs, and job logs. Ask “why is CI failing on this PR?” with the link.

For a group project, one person can connect the repository and share the Code Project. Another member can ask a shape to investigate a failing test; the group can review the explanation and then request a fix. Ask for the changed files and test result in the chat. If you request publication, check the returned branch or pull-request link in GitHub. Sharing the project permits those actions; it does not mean a task has already run or a change has been published.

## Share your computer with chat members

Let specific members use your computer in a chat where you've allowed it.

1. Open **Connect your computer** in that chat.
2. Under **Shared computer access**, select **Share with people** and choose up to 50 members.
3. Choose the permission:
   - **Read-only**: members can read files and ask Codex or Claude Code for read-only work. Commands, file changes, screen control, and opening apps are blocked.
   - **Can make changes**: members can run commands, change files, open apps, use the screen, keyboard, and mouse, and use Codex or Claude Code to make changes with your local accounts.
4. Choose when access ends: **1 hour**, **24 hours**, or **Until I turn it off**.
5. Select **Save access**. Saving replaces the computer's current shared access in that chat.

Each share shows its permission, who has it, and when it expires, or **Until turned off**. Select **Revoke** to end it early. Shapes check the current permission before every action, so revoking or expiry applies to the next action; it doesn't undo work already done. Only you can share your computer, and members who leave the chat lose access.

## Work together on a connected computer

### Bring a local file into the discussion

Maya has the trip budget on her laptop. The rest of the family needs to compare two accommodation options.

1. Maya connects her computer, allows the family chat, and asks the shape to read the named budget file and summarize the relevant totals in that chat.
2. Everyone compares the summary and adds missing requirements. They can discuss what Maya shared without getting access to her computer.
3. Maya asks for any further file reads or changes herself, or explicitly [shares computer access](#share-your-computer-with-chat-members) with selected people.

Give the file's location and the question you want answered. Check the figures against the original file before deciding. A summary in the chat is shared information; it does not give other members permission to browse the rest of the computer.

### Let a friend review without changing files

For a class project, Maya can share **Read-only** access with Drew. Drew then asks a shape to review the named folder on Maya's computer, or use her configured local Codex or Claude Code for a review. The shape can post findings in the chat or the [thread](/threads) where Drew asked.

Read-only access supports file reads and agent inspection, not direct commands, edits, or opening apps. If the next step requires changes, Maya must save **Can make changes** access for Drew before Drew's request can make them. Saying “you can edit it” in the conversation does not change that saved permission.

### Make a change and review the result together

With **Can make changes** access, Drew can ask the shape to use Maya's named computer to fix a specific issue and run the relevant checks. For example: “Fix the date calculation in this project, run its tests, and leave the changes for us to review.” The local agent uses Maya's installed setup and accounts.

Keep the computer online while the job runs. Ask for the changed files, check results, and any unfinished steps in the conversation, then inspect the actual files on that computer. A started job or finished status alone does not prove that the requested fix worked or that a branch was published. Revoking access prevents later actions; do not assume it cancels work already running.

## How it handles a busy or dropped connection

- **Busy computer:** when another chat's command is already running on your computer, the next one waits up to 60 seconds for its turn instead of failing.
- **Missing folder or file:** the shape says the path is missing, not that your computer is offline.
- **Dropped connection:** a command that already started isn't run a second time when the connection comes back.
- **One repository at a time:** a code search stays in the repository the task is about.

## Troubleshooting

### Connect your computer isn't in the + menu

It appears only in Agent chats. Ask a chat owner to switch the chat to **Agent**; see [Chat, Agent, and Auto](/chat-and-agent-modes#switch-an-existing-chat).

### My computer shows Offline

Make sure it's on, signed in, and connected to the internet, then select **Check for my computer** in **Settings** → **Computers**. If it still does not reconnect, open shapes.inc on that computer. If **This Mac** or **This PC** shows **Disconnected**, select **Reconnect this Mac** or **Reconnect this PC**.

### My Windows PC refuses every command

Update the app with **Help** → **Check for Updates…**. Versions 1.1.3 and 1.1.4 improved a connected PC getting stuck after one lost command result; this is still being watched. If it keeps happening, select **Disconnect this PC**, then **Reconnect this PC**.

### Connect this Mac doesn't finish

- Check that the Mac is online, select **Cancel**, and try again.
- If the app says **Update the app to connect this Mac**, choose **shapes.inc** → **Check for Updates…**, or download the current version from [shapes.inc/downloads](https://shapes.inc/downloads).
- If setup shows **Open Login Items Settings**, macOS is stopping shapes.inc from running in the background. Select it, allow shapes.inc in **System Settings** → **General** → **Login Items & Extensions**, then connect again.
- If you're signed out, the step shows **Sign in** instead. Sign in first, then connect.

<a id="screen-or-keyboard-control-doesnt-work" />

### Screen or keyboard control doesn't work

If **Keyboard and mouse** or **Screen recording** stays off after you allow it:

- **Keyboard and mouse:** in **System Settings** → **Privacy & Security** → **Accessibility**, turn on **ComputerConnectionHost**.
- **Screen recording:** in **Privacy & Security** → **Screen & System Audio Recording**, turn on shapes.inc. If it isn't listed, select **+** and add shapes.inc from Applications. Quit and reopen shapes.inc if macOS asks.

A **Read-only** share can't use the screen, keyboard, or mouse; the computer's owner must save **Can make changes** for that member.

### I can't share my computer

First allow your computer in that chat. You also need at least one other member in the chat to share with.
