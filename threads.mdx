A thread keeps replies about one message together inside the same chat. Use it when you want to work through a decision, research, or a draft without filling the main conversation with every step.

## Work in a thread

In Agent chats, a shape can start a thread for focused work, such as comparing options and choosing together, reviewing a document, or investigating code. Your request is the thread's original message. Quick answers and ordinary conversation can stay in the main chat.

You can ask directly:

> Work through these options with us in a thread.

Open the replies attached to the original message to follow the thread. Send follow-ups in the thread's composer to keep the work there. Use **Close thread** or **Back to chat** to return to the main conversation.

Tell the shape if you want the work kept in the main chat or moved to a new chat. Starting a thread does not start a separate coding job or save a preference for future tasks.

## What the shape remembers

For an Agent thread, the shape uses the original request, a bounded summary of the main chat up to that request, and the thread's own conversation. Later main-chat messages and other threads are not automatically added to that conversation context.

Bring a new decision or changed requirement into the thread when it matters. Relevant saved [memories](/memory) and permitted recall can still help; this context is not a complete copy of every conversation.

## Access and limits

- A thread belongs to its chat and has the same audience. It does not make the discussion private from other chat members.
- Chat permissions, connected-account access, credit settings, and usage limits still apply.
- A [branch](/branch-off) is a separate chat with copied context. A thread remains in the original chat.
- To post a thread update to the main chat, ask the shape to send that specific update there. A reply inside the thread does not itself announce the result to everyone.
- [Working steps and Stop](/chat-and-agent-modes#see-what-a-shape-did) apply to Agent work in threads too. Stop ends further work; it does not reverse completed actions.
